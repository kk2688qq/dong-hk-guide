**它的阅读模型（要学的是这个，不是抄它的配色）**

- 首页 `index.html`（约 99KB，**单文件**）本身就是检索器：侧栏按章节导航 + 关键词搜索 + 成本维度多选筛选。

**它的写法规则（内容层已在上一轮对齐，页面层继续遵守）**

## 5. 页面技术约束

1. **自包含单文件**：产物 HTML 不得依赖任何外部资源（字体、CDN、图片一律内联或去掉）。验收方法：抓产物里所有 `http(s)://` 引用，除自身仓库/发布地址外应为空。
2. **断网可读、可微信转发**：这是主要分发方式。
3. **不依赖 JS 也能读全文**：卡片是**服务端渲染**的静态 HTML，搜索/筛选只是增强。理由：AI 联网抓取（`llms.txt`）和搜索引擎都要能拿到正文。
4. **移动端优先**：竖屏 375–430px 宽是主场景；桌面是次要场景。
5. **打印／PDF**：打印样式要自动展开所有折叠明细（别把内容印丢）。
6. **深色／浅色**：用 class 驱动（`<html class="dark">`），跟随系统 + 手动开关，两种都要能验证。
7. **可深链**：`?q=关键词` 能带着搜索词直接打开（转发时好用）；条目锚点 `#HK-0XX` 可用。
8. **条数由脚本统计**，页面上出现的「49 条」「A 级 84%」这类数字不要手写死。

## 6. 已知的坑（上一轮踩过，别重踩）

1. **`.lede` 不能用 `<p>` 装 markdown 输出**。markdown 渲染出内层 `<p>`，会造成非法嵌套，浏览器把外层截成**空框**、文字掉到框外。容器一律用 `<div>`。（上一轮首版「说人话」框全空就是它。）
2. **f-string 里写内联 `<script>`／CSS，`{` `}` 必须双写成 `{{` `}}`**，否则被当表达式求值。
3. **搜索索引不要写进 `data-q`**。每条正文抄一遍会让单文件体积翻倍（实测 1187KB → 运行时用 `textContent` 建索引后 733KB）。
4. **主题不要只靠 `@media (prefers-color-scheme)`**。无头 Chrome 测不到，且读者没法手动切；改成 class 驱动。
5. **含反引号的文本一律用单引号 heredoc**（`<<'EOF'`），否则 shell 会做命令替换。（写脚本、写日志时适用。）
6. **改完必须 `git diff --numstat` 看改动行数**：只改呈现层时，`book/` 下每个文件改动行数应为 0；一旦发现正文被动了，立刻回退。
